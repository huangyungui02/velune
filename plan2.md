# StarSea iOS Frontend Implementation Plan

## Goal

Implement the iOS StarSea flow so a user can write an opening thought, immediately enter a new StarSea conversation view, keep talking with the AI through `/starsea`, see resonance match cards, and optionally settle the conversation into a generated glimmer record when leaving.

The new product meaning is:

- The text the user writes first is not a glimmer.
- A glimmer is the settled diary-like reflection generated by the StarSea collect branch.
- StarSea conversation history does not need to be saved on iOS for now.
- Profile should show all settled glimmer records.

## Backend Contract Changes

### `/starsea` request shape

Update `/starsea` so it no longer requires an existing `glimmerId`.

First turn:

```json
{
  "content": "The user's opening thought"
}
```

Follow-up turns:

```json
{
  "threadId": "existing-thread-id",
  "content": "The user's next message"
}
```

Settle turn:

```json
{
  "threadId": "existing-thread-id",
  "intent": "collect"
}
```

Notes:

- The backend should create a new `threadId` for the first turn.
- The same `threadId` should be used as the LangGraph checkpoint thread id for follow-up turns.
- Directly leaving a conversation should not write a glimmer.
- The checkpoint can remain on the backend naturally after direct leave.

### Router behavior

Use the existing router node to decide between:

- `starsea`: normal conversation turn.
- `collect`: settle and generate a diary-like reflection.

When `intent` is `collect`, the route should enter the `collect` branch.

### SSE events

Use these front-facing events:

```json
{ "type": "ready", "threadId": "..." }
```

```json
{ "type": "delta", "delta": "..." }
```

```json
{
  "type": "resonance_match",
  "matches": [
    {
      "name": "Zhuangzi",
      "line": "A short sentence that resonates with the current thought."
    }
  ]
}
```

```json
{ "type": "done", "threadId": "..." }
```

```json
{
  "type": "settled",
  "glimmer": {
    "id": "...",
    "content": "...",
    "createdAt": "..."
  }
}
```

```json
{ "type": "error", "message": "..." }
```

Rename the old `thought_matches` event to `resonance_match`.

For `resonance_match`, only return the fields the iOS UI needs:

- `name`
- `line`

### Glimmer creation

Only the `collect` branch should write to the `glimmers` table.

The generated glimmer should be:

- owned by the current user
- connected to the settled StarSea thread if the schema supports it
- ordered by `created_at` like existing glimmer history
- suitable for display as a diary/reflection, not as a raw chat message

## iOS Implementation

### StarSea entry flow

Files likely involved:

- `ios/Velune/Velune/Views/StarSea/StarSeaView.swift`
- `ios/Velune/Velune/Views/StarSea/StarSeaComposerCover.swift`
- new `ios/Velune/Velune/Views/StarSea/StarSeaConversationView.swift`
- new `ios/Velune/Velune/Services/StarSeaStreamService.swift`

Current behavior:

- User writes text in `StarSeaComposerCover`.
- Done dismisses the cover and leaves the text as a local draft/card.

New behavior:

1. User taps the write button.
2. `StarSeaComposerCover` opens.
3. User writes an opening thought.
4. User taps done.
5. The cover closes.
6. The app immediately navigates to `StarSeaConversationView`.
7. The user's opening thought appears as the first user chat bubble.
8. `StarSeaConversationView` immediately starts streaming from `/starsea`.

Do not create a `Glimmer` at this point.

### StarSea navigation

Add a local route inside `StarSeaView`:

```swift
private enum StarSeaRoute: Hashable {
    case conversation(openingText: String)
}
```

Use `NavigationStack(path:)` so StarSea owns its own navigation.

When composer is done:

- trim the text
- ignore empty values
- clear local draft state
- push `.conversation(openingText:)`

### StarSea conversation state

Use view-local state for now.

Suggested model:

```swift
struct StarSeaMessage: Identifiable, Hashable {
    enum Role: Hashable {
        case user
        case assistant
    }

    let id: UUID
    let role: Role
    var content: String
}
```

Suggested conversation state:

```swift
@State private var threadId: String?
@State private var messages: [StarSeaMessage] = []
@State private var inputText = ""
@State private var isStreaming = false
@State private var errorMessage: String?
@State private var hasStarted = false
@State private var resonanceMatches: [StarSeaResonanceMatch] = []
@State private var leaveConfirmation: StarSeaLeaveConfirmation?
```

The conversation should not persist locally for now.

### StarSea stream service

Create `StarSeaStreamService` and reuse `APISSEClient`.

The service should expose an async stream similar to `ChatStreamService`:

```swift
enum StarSeaStreamService {
    enum Event {
        case ready(threadId: String)
        case delta(String)
        case resonanceMatch([StarSeaResonanceMatch])
        case done(threadId: String?)
        case settled(StarSeaSettledGlimmer)
    }
}
```

Normal send:

```swift
StarSeaStreamService.stream(
    threadId: threadId,
    content: content,
    intent: nil
)
```

Collect send:

```swift
StarSeaStreamService.stream(
    threadId: threadId,
    content: nil,
    intent: .collect
)
```

The service should map SSE `error` payloads into thrown errors, following the existing `ChatStreamService` pattern.

### Conversation behavior

Initial load:

1. Append user message with the opening text.
2. Append an empty assistant message.
3. Call `/starsea` with `{ content }`.
4. On `ready`, store `threadId`.
5. On `delta`, append to the assistant message.
6. On `resonance_match`, update the match cards.
7. On `done`, finish the current turn.

Follow-up send:

1. Require a non-empty input and a non-empty `threadId`.
2. Append user message.
3. Append empty assistant message.
4. Call `/starsea` with `{ threadId, content }`.
5. Stream events into the UI the same way as the first turn.

Avoid sending a follow-up while another stream is active.

### Resonance match cards

Render `resonance_match` as cards, not chat bubbles.

Each card should show:

- person name
- one short line

First version behavior:

- display only
- no navigation
- no detail sheet

Visual direction:

- calm StarSea style
- glass-like surface if it fits existing iOS 26 style
- compact enough to sit under the latest assistant response
- accessible text labels

### Leave and settle flow

Back button and system back gesture should not immediately pop while a StarSea conversation is active.

When the user tries to leave, show a confirmation dialog:

- `沉淀并离开`
- `直接离开`
- `继续`

`继续`:

- dismiss the dialog
- stay on the conversation

`直接离开`:

- cancel any active stream if needed
- pop the view
- do not write a glimmer
- do not save conversation history on iOS

`沉淀并离开`:

1. Require an existing `threadId`.
2. Call `/starsea` with `{ threadId, intent: "collect" }`.
3. Keep the UI in a settling/loading state.
4. Wait for `settled`.
5. Pop the view after the settled glimmer is returned.
6. Do not separately insert the glimmer from iOS; the backend owns glimmer creation.

If collecting fails:

- show an error
- keep the user on the conversation
- allow retry, direct leave, or continue

### Profile glimmer records

Files likely involved:

- `ios/Velune/Velune/Views/Profile/ProfileView.swift`
- new `ios/Velune/Velune/Views/Profile/GlimmerRecordsView.swift`
- `ios/Velune/Velune/Models/Glimmer.swift`

Add a Profile entry for settled records.

Suggested label:

- Chinese: `沉淀记录`
- English: `Reflections`

The records view should:

- fetch current user's glimmers
- order by `created_at` descending
- show content and date
- include loading, empty, and error states
- use existing `Glimmer.getPage(...)` or `Glimmer.getAll()`

First version can be a simple list of cards without a detail page.

### Copy and localization

Add or update localized strings for:

- StarSea conversation input placeholder
- leave confirmation title/message
- settle and leave
- leave directly
- continue
- settling progress
- resonance match section/card accessibility
- Profile entry for settled records
- glimmer records empty/error states

Use existing localization style in:

- `ios/Velune/Velune/zh-Hans.lproj/Localizable.strings`
- `ios/Velune/Velune/en.lproj/Localizable.strings`

## Implementation Order

1. Update backend `/starsea` request parsing and thread creation.
2. Route `intent: "collect"` into the LangGraph `collect` branch.
3. Rename `thought_matches` to `resonance_match` and reduce match payload to `name` and `line`.
4. Add backend `settled` SSE event after collect writes the generated glimmer.
5. Add `StarSeaStreamService` on iOS.
6. Add `StarSeaConversationView`.
7. Change `StarSeaView` composer completion to navigate into the conversation instead of creating or showing a glimmer draft.
8. Add leave confirmation and collect flow.
9. Add Profile glimmer records entry and list view.
10. Add localization.
11. Build and run iOS verification.

## Verification

Backend:

- `/starsea` first turn with only `content` returns `ready`, streams `delta`, and ends with `done`.
- `/starsea` follow-up with `threadId + content` continues the same checkpoint.
- `/starsea` with `threadId + intent: "collect"` writes one glimmer and returns `settled`.
- Direct leave path does not write a glimmer.
- `resonance_match` payload contains only `name` and `line`.

iOS:

- Writing an opening thought enters `StarSeaConversationView` immediately.
- First user bubble uses the opening thought.
- Assistant streams into the latest assistant bubble.
- Follow-up messages keep using the same `threadId`.
- `resonance_match` renders as cards.
- Back button and swipe-back show the leave confirmation.
- `沉淀并离开` waits for `settled`, then exits.
- `直接离开` exits without creating a glimmer.
- Profile shows settled glimmer records after collect succeeds.

Build:

- Run an iOS simulator build for the `Velune` scheme.
- If possible, run the app and manually verify the StarSea flow with the configured API.
