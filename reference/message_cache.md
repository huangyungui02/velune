# Chat 缓存策略（方法与流程）

## 目的

- 打开会话更快：先本地可用，再远端补齐。
- 减少重复全量拉取：消息优先走增量同步。
- 保持流程简单：明确入口、明确刷新时机。

## 方法更新

### `loadConversationSessions()`

- 现在只负责：读取本地会话缓存。
- 不再在这个方法里主动请求远端。

### `syncConversationSessionsOnMenuAppear()`

- 新增专用方法。
- 触发时机：用户点击右上角会话菜单，菜单出现时。
- 行为：
  - 本地已有缓存：远端拉最新一页做合并刷新。
  - 本地无缓存：远端全量分页拉取后合并。

### `loadMessages()`

- 读取策略改为“本地优先 + 增量同步 + 全量兜底”。
- 行为：
  1. 先尝试读取本地消息并立刻展示。
  2. 判断是否需要远端同步。
  3. 若命中本地 bucket：按时间游标拉取增量消息并与本地合并。
  4. 若增量为空但会话时间戳已更新：走一次全量拉取兜底。
  5. 若无 bucket：直接全量拉取。

### `Message.getHistory(sessionId:createdAfterOrAt:)`

- 新增消息增量拉取方法。
- 使用消息创建时间作为增量游标来源，带轻微重叠窗口，避免边界丢消息。

## 运行流程

### 1. 首次进入 ChatView

1. 调 `loadConversationSessions()`，先拿本地会话。
2. 调 `prepareConversation()`，进入 `loadMessages()`。
3. `loadMessages()` 先展示本地，再按规则增量/全量同步。

### 2. 切换已有会话

1. 先调 `loadConversationSessions()`，保证本地会话信息可用。
2. 再调 `prepareConversation()`，触发该会话的消息加载与同步。

### 3. 打开会话菜单

1. 菜单出现时触发 `syncConversationSessionsOnMenuAppear()`。
2. 本地列表先显示，远端刷新在后台合并回本地。
3. 刷新完成后菜单展示最新会话状态。

### 4. 消息同步策略（打开某个会话时）

1. 本地有缓存：立即显示。
2. 优先走增量同步。
3. 增量结果按消息 ID 合并去重并排序。
4. 发现“会话已更新但增量为空”时，全量拉取兜底。
5. 同步成功后回写本地缓存与游标。

## 错误处理

### 会话列表

- 本地有缓存且远端失败：继续显示本地。
- 本地无缓存且远端失败：显示错误与重试入口。

### 消息列表

- 本地有缓存且远端失败：继续显示本地。
- 本地无缓存且远端失败：显示错误态。

## 当前策略总结

- 会话列表：`loadConversationSessions()` 只本地，`syncConversationSessionsOnMenuAppear()` 在菜单出现时远端刷新。
- 消息列表：`loadMessages()` 先本地，再增量，同步异常时按条件全量兜底。
- 目标：更快打开、更少流量、行为可预期。
